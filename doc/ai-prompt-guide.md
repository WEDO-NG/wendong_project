# AI 调教指南 (Prompt Engineering Guide)

本文档旨在记录 **Wendong Project** 中 AI 助手的 Prompt 设计思路与调优策略，帮助开发者让 AI 变得更“聪明”、更符合业务场景。

---

## 一、核心原则 (Core Principles)

### 1. 立人设 (Persona)
不要让 AI 做“通用机器人”，要给它一个具体的身份。
> ❌ "你是一个 AI 助手。"
> ✅ "你是一个拥有 10 年经验的房地产投资顾问，性格幽默风趣，擅长用数据说话。"

### 2. 给上下文 (Context)
AI 没有记忆，也不知道你的业务数据，必须在 System Prompt 中注入。
> ✅ "当前数据库中有以下海景房资源：[...]"

### 3. 明确边界 (Boundaries)
告诉它**不能做什么**，防止胡言乱语。
> ✅ "如果用户问的问题与房地产无关，请礼貌地拒绝或转移话题。"
> ✅ "严禁编造数据，如果不确定，请说'我暂时没有相关信息'。"

### 4. 规定输出格式 (Output Format)
如果前端需要特定格式（如 Markdown 表格、JSON），必须明确说明。
> ✅ "请使用 Markdown 表格展示对比数据。"

---

## 二、System Prompt 模板

我们目前的 System Prompt 结构如下：

```markdown
# Role
你是一个 [角色名称]，服务于 "Wendong Project"。

# Tone
你的语言ta de风格是：[风格描述，如：专业、亲切、偶尔使用 Emoji]。

# Context (RAG)
以下是当前系统中的实时业务数据，请基于这些数据回答用户问题：
---
[注入的数据列表]
---

# Rules
1. 优先使用上述【Context】中的数据回答。
2. 如果用户问及【Context】之外的内容，请 [策略，如：使用通用知识回答 / 引导回业务话题]。
3. 回复长度控制在 [N] 字以内。
```

## 三、调优实战 (Optimization Cases)

### 场景 1：用户问“最近有什么新闻？”
*   **Bad Prompt**: "回答用户关于新闻的问题。" -> AI 可能会瞎编或说不知道。
*   **Good Prompt**: 
    1. 后端先查 News 表。
    2. 将 News 数据注入 System Context。
    3. Prompt: "请根据以下新闻列表，为用户生成一份简报，按时间倒序排列。"

### 场景 2：用户问“推荐个房子”
*   **Bad Prompt**: "推荐房子。"
*   **Good Prompt**: 
    1. 注入 Seascape 表数据。
    2. Prompt: "请根据用户的预算和喜好，从下面的列表中挑选最合适的 1-2 套房源，并解释推荐理由。不要简单罗列参数，要描绘居住体验。"

## 四、RAG (检索增强生成) 进阶策略

随着数据量增长，直接把所有数据塞进 Prompt 会导致 Token 溢出。我们需要引入更智能的检索策略：

1.  **关键词匹配**: 提取用户问题中的关键词（如“价格”、“海景”），只查询相关字段。
2.  **向量检索 (Vector Search)**: (Phase 4 规划)
    *   将业务数据 Embedding 存入向量数据库 (如 pgvector / Chroma)。
    *   将用户问题 Embedding。
    *   搜索最相似的 Top 5 数据块注入 Prompt。

## 五、测试与评估

如何判断 AI 变聪明了？
1.  **准确性**: 问它库里有的数据，看能不能答对价格、户型。
2.  **抗干扰性**: 问它“你是谁开发的”，看它是否按人设回答（而不是说我是 OpenAI 开发的）。
3.  **格式规范**: 看它是否输出了漂亮的 Markdown。
