# 阿里云镜像服务部署记录 (Aliyun ACR Deployment Log)

> 记录于 Phase 3 阶段：解决低配置服务器构建难题与国内网络环境问题。

## 1. 背景与挑战

在完成 Phase 3 的核心功能开发（DeepSeek 集成、SSE 流式对话、数据库对接）后，在尝试将项目部署到阿里云服务器（2核2G）时遇到了以下严重阻碍：

1.  **网络环境限制**：国内服务器环境无法顺畅拉取 Docker Hub 官方镜像（如 `node:18`），导致构建过程频频超时失败。
2.  **硬件资源瓶颈**：服务器配置较低（2C2G），直接在服务器上运行 `docker build` (包含 `npm install` 和 `webpack build`) 导致内存溢出 (OOM) 或系统卡死。
3.  **繁琐的手动流程**：尝试本地 `docker save` 打包 -> `scp` 上传 -> 服务器 `docker load`，虽然可行但文件巨大（数百MB），传输慢且操作繁琐，不适合频繁迭代。

## 2. 解决方案：阿里云容器镜像服务 (ACR)

为了彻底解决上述问题，我们采用了 **"本地构建 -> ACR 托管 -> 服务器拉取"** 的工业级交付流程。

### 2.1 架构优势

- **规避网络问题**：利用本地稳定的网络环境拉取基础镜像和 npm 依赖。
- **释放服务器压力**：编译、构建等高负载任务全部在本地完成，服务器仅负责拉取和运行成品镜像。
- **高速交付**：阿里云内网/高速节点拉取镜像速度极快（秒级）。

### 2.2 实施步骤

#### A. 基础设施准备

1.  开通阿里云容器镜像服务（个人版）。
2.  创建命名空间 `wendong-registry`。
3.  创建两个镜像仓库：
    - `server-node`: 后端服务
    - `web-react`: 前端 Nginx 服务

#### B. 自动化脚本 (本地)

创建并优化了 `scripts/build-prod.sh` 脚本，实现一键发布：

1.  自动登录阿里云 Registry。
2.  并行构建前端和后端 Docker 镜像。
3.  自动打标并推送到阿里云仓库。
4.  **优化点**：添加 `--progress=plain` 参数，解决构建过程"无动静"的焦虑，实时展示进度。

#### C. 服务器部署配置

更新 `docker-compose.prod.yml`：

1.  移除 `build` 字段，禁用服务器端构建。
2.  将 `image` 字段指向阿里云 ACR 地址（北京节点）。
3.  配置 Nginx 容器自动处理 80 端口映射。

## 3. 遇到的坑与填坑

### 问题 1: 脚本"卡死"误解

- **现象**：运行脚本输入密码后终端无反应。
- **原因**：Unix 密码输入默认为静默模式；Docker 构建默认隐藏详细日志。
- **解决**：解释静默输入机制；为 `docker build` 添加 `--progress=plain` 参数显示详细流。

### 问题 2: Docker Desktop 未启动

- **现象**：`Cannot connect to the Docker daemon`。
- **解决**：启动本地 Docker Desktop 后解决。

### 问题 3: 端口冲突 (Address already in use)

- **现象**：服务器拉取镜像成功，但启动时报 80 端口被占用。
- **解决**：
  1.  `docker rm -f` 清理旧容器。
  2.  `systemctl stop nginx` 停止宿主机占用的 Nginx 进程。
  3.  重启容器成功。

### 问题 4: Prisma Seed 执行困难

- **现象**：生产镜像裁剪了 `devDependencies`，导致无法直接运行 `ts-node` 执行种子数据。
- **解决**：采用临时安装依赖或直接执行编译后 JS 的方案。

## 4. 最终成果

- ✅ **成功部署**：前后端服务在阿里云服务器上稳定运行。
- ✅ **极速更新**：代码变更后，本地一键脚本推送，服务器秒级拉取，无需漫长等待编译。
- ✅ **功能验证**：Web 页面访问正常 (80端口)，DeepSeek AI 对话功能连接正常。
